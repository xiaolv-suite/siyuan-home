## 二、 真实浏览器从零自用当场抓获并根治的 8 项生产级缺陷

此前单元测试（运行未压缩 TS 源码 + Mock 内核返回值）与存量老靶场（历史已建好数据库且含几十行旧数据）完全掩盖了以下 **新用户首次安装与日常连贯操作** 才会暴露的 8 项真实缺陷，本轮已全部定位修复并实测闭环：

1. **`[P0 致命]` Terser `booleans_as_integers: true` 导致全新工作区建库 100% 失败（[`vite.config.ts`](../../vite.config.ts)、[`scripts/smoke-test.mjs`](../../scripts/smoke-test.mjs)）**
   - **现场表现**：空白工作区首次点击向导「完成引导」，全部 9 个模块建库失败，报错 `[/api/av/renderAttributeView] Field [createIfNotExist] has an invalid type: json: cannot unmarshal number into Go value of type bool`。
   - **根因与修复**：`vite.config.ts` 开启 `booleans_as_integers: true` 把 `{ createIfNotExist: true, isDetached: true, isNotEmpty: true }` 压成了 `1/0`，Go `encoding/json` 强类型反序列化直接拒收。已显式设为 `booleans_as_integers: false`，并在 `smoke-test.mjs` 新增第 7 道静态门禁守卫。
2. **`[P0 致命]` 思源 Go 内核空单元格零值哨兵派生大批量“公元 1 年”幽灵逾期提醒（[`src/core/hub/providers.ts`](../../src/core/hub/providers.ts)、[`src/core/avcell.ts`](../../src/core/avcell.ts)）**
   - **现场表现**：仅新建 1 张未填审验日的身份证和 1 辆未填年检日的汽车，立刻弹出 `逾期 12 件待处理` 红条告警！
   - **根因与修复**：思源 Go 内核对未填写的日期列返回 `{ date: { content: -62135596800000, isNotEmpty: false } }`（Go `time.Time{}` 零值 = `0001-01-01`），对未填写的数字列返回 `{ number: { content: 0, isNotEmpty: false } }`。`providers.ts` 与 `avcell.ts` 此前未过滤 `isNotEmpty === false` 与零值哨兵，把所有空日期列当成了逾期 73 万天的事项。已严格补齐 `isNotEmpty === false` 及零值拦截，并新增专项回归单测。
3. **`[P0 崩溃]` 切换到空台账或新开启未建库模块时触发 `effect_update_depth_exceeded` 整屏崩溃（[`src/panels/screens/ledger.svelte`](../../src/panels/screens/ledger.svelte)）**
   - **现场表现**：从有记录的「证件」台账切换到刚启用的「车辆」模块，台账屏立刻崩溃进入 `ErrorBoundary`（`https://svelte.dev/e/effect_update_depth_exceeded`）。
   - **根因与修复**：`ledger.svelte` 的 `$effect` 在同步帧内直接调用 `load(isSwitch)`，`load` 内部先读取 `rows.length === 0` 再写回新数组 `rows = []` / `rows = res.rows`，在空表场景下形成无限响应式自触发死循环。已用 Svelte 5 `untrack(() => void load(isSwitch))` 彻底隔离内部状态写回。
4. **`[P1 断链]` 新手向导预置家庭成员未同步写入 `members` 台账（[`src/index.ts`](../../src/index.ts)）**
   - **现场表现**：向导生成的 `我 (本人)`、`配偶`、`孩子`、`长辈` 全部没有 `avItemId`，在新建记录成员下拉框中全部置灰显示 `· 未关联台账` 无法选择。
   - **根因与修复**：`finishOnboarding` 原先在 `ensureCoreLedgers()` 建库前直接往 `settings.members` 塞裸对象。已改为先完成 `ensureCoreLedgers()` 建库，再调用 `addMember` 真实建行回填 `avItemId`。
5. **`[P1 缺失]` 新建证件弹窗遗漏渲染证件专属标量字段与存放位置（[`src/panels/screens/ledger-record-modal.svelte`](../../src/panels/screens/ledger-record-modal.svelte)、[`src/panels/screens/ledger-record-more.svelte`](../../src/panels/screens/ledger-record-more.svelte)、[`src/core/location-dialog.ts`](../../src/core/location-dialog.ts)）**
   - **现场表现**：新建身份证时弹窗不显示「身份证号码」「存放位置」等输入框。
   - **根因与修复**：历史瘦身拆分组件时 `additionalCols` 排除了证件字段但忘记将 `certificateScalarCols` 传入 `<LedgerRecordMore>`。已将其合并传入并在选中证件类别时自动展开，同时在 `location-dialog.ts` 补齐 `store_place` 字段索引。
6. **`[P1 交互]` 快速记录「记日常流水」保存成功后弹窗永不自动关闭 + 重开不刷新新建车辆/家务（[`src/panels/quick-event-flow.svelte`](../../src/panels/quick-event-flow.svelte)、[`src/panels/quick-capture.svelte`](../../src/panels/quick-capture.svelte)）**
   - **根因与修复**：5 个 `submitQuick*` 函数均在 `finally { saving = false }` 之前调用 `onClose()`，而父组件 `close()` 首行判断 `if (saving) return;` 直接拦截了关窗！已在调用 `onClose()` 前先复位 `saving = false`，并在每次打开快速记录弹层时自动触发 `reloadContext()`。
7. **`[P1 竞态]` 总览页点击「📍 东西放哪了」跨屏 `setTimeout(..., 60)` 丢失事件（[`src/core/overview-modals.ts`](../../src/core/overview-modals.ts)、[`src/panels/screens/overview.svelte`](../../src/panels/screens/overview.svelte)）**
   - **根因与修复**：原逻辑先 `onGoto("ledger")` 懒加载台账组件再隔 `60ms` 盲发 `CustomEvent`，首次加载超过 `60ms` 时事件直接丢失。已改为在 `overview-modals.ts` 直接调用 `openLocationIndexDialog` 原地打开弹窗。
8. **`[P1 状态]` 顶栏「🛡 只读访客模式」切换后横幅与高亮不即时响应（[`src/panels/tab-panel.svelte`](../../src/panels/tab-panel.svelte)、[`src/panels/screens/ledger.svelte`](../../src/panels/screens/ledger.svelte)）**
   - **根因与修复**：`isGuestMode` 读取普通对象 `plugin.runtime.guestModeActive` 时漏读 `void version`，导致点击后 UI 不更新。已补齐 `void version` 依赖与 `emitHubChanged()` 广播。

## 二（再续）、 三轮思源原生文档落地、列序正序化与跨屏联动收口（`v0.5.188`）

针对“确保每个功能点击有效、有反馈，并且在思源笔记里的文档真正落地”，在隔离环境深入核查思源文档树（`🏠 小驴管家` 笔记本内各 `台账 · XXX` 文档）的 Protyle 渲染结果与跳转联动，抓出并彻底根治以下 4 项关键问题：

15. **`[P0 思源文档空表]` 台账文档内 `<div class="av">` 的 `data-av-id` 与 `dbRefs.avId`（`data-node-id`）分裂，导致在思源笔记树中点开台账文档时表格为空（[`src/core/siyuan.ts`](../../src/core/siyuan.ts)）**
    - **现场表现**：在插件面板内能看到已录入的身份证、成员、车辆记录，但在思源左侧文档树点开 `台账 · 证件管理` 文档时，文档内的原生属性视图表格却显示为 `0` 行空表。
    - **根因与修复**：`createAttributeView(docId, avIdSeed)` 插入 `<div data-type="NodeAttributeView" data-av-id="${avIdSeed}" data-av-type="table"></div>` 时未带块 ID 声明，思源为其分配了新的 `data-node-id`（被插件当作 `dbRefs.avId` 建库写数据），而文档内 `<div class="av">` 仍指向空的 `data-av-id="${avIdSeed}"`。已在插入时附带 Kramdown IAL `{: id="${avIdSeed}"}`，让 `data-node-id` 与 `data-av-id` 100% 合一，点开思源文档即刻渲染全部真实数据。
16. **`[P0 原生文档列序倒置 & 同义列碰撞]` 思源原生表格列顺序完全倒置（`主键` 被挤到第 90 列）且 `expiry`/`due` 共享同列 ID 产生重复提醒（[`src/core/siyuan.ts`](../../src/core/siyuan.ts)、[`src/core/provisioner.ts`](../../src/core/provisioner.ts)）**
    - **现场表现**：在思源文档中查看原生表格时，第 1 列变成了 `其他证件扫描件`，而 `主键`（名称）、`成员`、`分类` 被挤到了最末尾第 88~90 列；同时 `due`（签注日）因别名命中复用了 `expiry`（到期日）的列 ID，导致录入 1 张身份证派生出 2 条同日重复提醒。
    - **根因与修复**：① `addAttributeViewColumn` 原先固定传 `previousKeyID: ""`（思源内核将空串视为插到第 0 列最前），现改为在 `ensureColumns` 中从 `主键` 列起链式传入 `previousKeyID`，实测原生表格列序恢复为 `主键 -> 成员 -> 分类 -> 状态` 正序；② `ensureColumns` 匹配既有列时排除已被其他字段占用的列 ID（`!usedColIds.has(...)`），彻底根除同表字段碰撞。
17. **`[P0 点击定位失效]` 提醒卡片「定位」、日历事项点击与详情抽屉「在文档中打开」传入 detached 行 `itemID` 导致无法打开思源文档（[`src/index.ts`](../../src/index.ts)）**
    - **现场表现**：点击提醒卡片的「定位」或详情抽屉的「在文档中打开」时，因 `row.itemID` 是属性视图 detached 条目 ID（不在思源 `blocks` 表中），`openTab` 无法打开文档。
    - **根因与修复**：重构 `showTabDocs(docId, blockId)`，优先打开所属台账文档 `docId`，并异步核实 `blockId` 是否为 `blocks` 表中的真实绑定块，若是则进一步聚焦高亮。
18. **`[P1 联动与对齐]` 总览 Bento「今日焦点」卡片下钻联动筛选、快捷「记待买/随手便签」即时刷新后台台账、抽屉保存回执与成员表单底栏右对齐**
    - **修复**：Bento「今日焦点」点击时同步设置 `hubDueWithin = "7"` 与成员筛选；`submitQuickShopping` / `submitQuickSnippet` 保存后触发 `refreshHub` 实时刷新台账；抽屉全量编辑无改动保存亦给出明确回执；`.lv-member-editor-actions` 补齐 `grid-column: 1 / -1; justify-content: flex-end;`。
